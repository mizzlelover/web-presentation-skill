# KN-INT-001 · Interaction Patterns · 交互模式

## Core claim
交互的唯一合法目标：降低理解成本，或支持受众自主探索。每个交互必须写 purpose。

## 词汇表与适用
| 交互 | 降低什么成本 / 支持什么探索 |
|---|---|
| hover | 辅助信息的按需查看（不增主画面负荷） |
| click/expand | 细节按需展开（Segmenting 的交互化） |
| drill-down | 汇总→明细的探索路径 |
| slider/scrub | "如果参数变会怎样"的心智模型建构 |
| filter | 在多维数据中找到"与我相关的"子集 |
| toggle | 两种视图/假设的对比 |
| compare | 并置差异 |
| explore | 开放数据集/模型的自由探索（Reader Mode 为主） |

## Boundary
- Stage Mode 现场：交互必须简单、确定、可回退——现场探索失控是事故。
- 交互不能替代叙事主线：Core Path 必须不依赖任何交互即可完整理解（交互是增强，不是门槛）。
- 首屏/每幕核心内容不得藏在交互之后（对 Reader/Print 退化致命）。
