技术上只新增三处组件，其余全部复用

新增三处：统一身份服务、数据服务网关、指标服务；其余复用既有系统。

新增 · 统一身份服务
手机号/实名为统一标识；跨渠道归并；与既有账号体系对接。
新增 · 数据服务网关
统一鉴权、限流、审计；对外只暴露服务接口。
新增 · 指标服务
唯一口径解析与计算入口。
复用 · 既有系统
数据仓库、调度、内容管理、账号体系。
（开场设边界）先划改动面：新增只有三处——统一身份服务、数据服务网关、指标服务。仓库、调度、内容管理、账号体系全部复用。不建中台，不迁历史数据。下面按集成、数据、接口、权限、运维五块讲。

权限：默认拒绝 + 数据级 + 全链路留痕

权限三条：默认拒绝、数据级授权、全链路审计。

S1
默认拒绝
未显式授权的数据域不可访问。
S2
数据级授权
字段级 + 数据域级两级授权。
S3
全链路审计
人 / 时间 / 口径 / 范围可回溯。
（面向安全）三条：默认拒绝，没授权的域访问不了；数据级授权，字段级和数据域级两级；全链路审计，谁取的、什么时候、用的哪个口径、拿了多大范围，都能追。身份断言由身份服务统一提供，不在各处重复实现。
权限：默认拒绝 / 数据级授权（字段 + 数据域）/ 全链路审计；身份断言统一由身份服务提供。

源材料：安全方案（样例）

上线策略：灰度、双跑、可回滚

灰度发布、双跑比对、一键回滚。

灰度
分批切流
按渠道分批，先 10% 流量。
双跑
差异比对
新旧路径并行；差异率 >1% 即暂停。
回滚
开关回退
旧路径保留一季度；网关开关一键回退。
（逐条）上线三步：灰度，按渠道分批，先放 10%；双跑，新旧路径并行比对，差异超过 1% 就暂停；回滚，旧路径保留一个季度，网关上一个开关就能退回来。身份服务和网关都是无状态，直接纳入既有监控，不增加新的运维体系。
上线：灰度（先 10%）→ 双跑（差异率 >1% 暂停）→ 回滚（旧路径保留一季度，网关开关一键回退）；身份/网关无状态，纳入既有监控。
