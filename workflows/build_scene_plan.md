# Workflow: Build Scene Plan — Scene 规划

## 输入
Argument Map + Presentation Strategy。

## 步骤
1. **拆 Scene**：每个 Scene 指定唯一 cognitive_job（15 选 1，§18）。一幕承担多个 job 时考虑拆分；Reader Mode 例外需注明。
2. **标题**：按 KN-PRES-002 选标题类型并写 rationale；assertion 必须是可证伪陈述句。
3. **写 stage / reader 双内容**（§57）：stage 精简（视觉+断言），reader 完整自足；speaker_notes 独立（§86）。
4. **讲者-屏幕分工**（§58）：填 screen_role / speaker_role，避免"屏幕写一遍、讲者读一遍"。
5. **认知负荷曲线**：为全部 Scene 标负荷，画出曲线，确认无连续 HIGH 无缓冲（§23）。
6. **Presentation Graph**（§33/§35）：定义 core_path、optional_paths、deep_dives、evidence_appendix、分支触发条件（现场什么信号→走哪条分支）。
7. **视觉语义**：为每幕选 visual_semantics 组件类型（§27 语义组件，不是模板）。
8. **渲染层级**：逐幕选 L0–L6 并写 render_rationale（§81/§82）。默认从 L1 起，升级必须给理由。
9. **动效/交互意图**：有需要的幕声明 motion_intent 与 interaction（含 purpose）；没有就留空——空是合法答案。

## 输出
- Scene Plan 表（id / role / cognitive_job / headline / load / render_level / semantics / graph 连接）
- 认知负荷曲线图（文本图即可）
- 分支触发表

## 禁止
- 禁止逐幕美化描述（颜色/阴影属于渲染阶段）。
- 禁止"全部 L3 起步"式批量升级。
