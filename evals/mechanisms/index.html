机制正反例画廊

25 条机制，每条给出正例与反例对照，并导出可执行的渲染规则。所有片段使用生产组件类名（runtime/components/components.css），因此本页同时是组件契约的回归夹具。

M01

一致性 Coherence

cognition/multimedia-learning · KN-MML-001

排除与学习目标无关的材料（装饰、背景音、无关图文）。

✓ 正例
促销转化率
本季度 6.2%，环比 +1.4pp。
✕ 反例
🎉✨🚀 超劲爆！促销转化率 🎉✨🚀
（此处插入无关插画、背景音乐、闪烁边框）本季度 6.2%。

导出的渲染规则：Renderer 不得为「丰富度」自动添加装饰元素；每个视觉元素必须能回答「它承担什么认知任务」。

证据/依据：Sundararajan & Adesope 2020 元分析：诱惑性细节降低学习效果（中文材料 g=-0.75）

M02

线索 Signaling

cognition/attention-fluency · KN-ATT-001

用线索突出组织的真实结构，而非到处加亮。

✓ 正例
本幕唯一重点
只强调一处结构。
次要信息
常规样式。
次要信息
常规样式。
✕ 反例
★ 加粗 ★
★ 高亮 ★
★ 荧光 ★

导出的渲染规则：每幕强调元素数量上限：1 处（必要时 ≤2）；超限时 Renderer 必须降级非结构元素。

证据/依据：de Koning 2009 综述；谢和平 2016 中文元分析 g=0.53（与 Schneider 2018 独立互证）

M03

冗余 Redundancy

cognition/multimedia-learning · KN-MML-002

屏幕文字与讲解内容不应逐字重复（Stage 模式）；但在 Reader 模式需要完整文字。

✓ 正例
屏幕给结论与结构，讲者补充解释与细节。

Reader 模式：本页完整论述见 wp-reader 层

✕ 反例
（屏幕上整段照抄讲者将逐字念出的 120 字讲稿……）

导出的渲染规则：Renderer 依据 mode 分流：Stage 屏幕承载结论/结构，Reader 承载完整文本；禁止把 speaker_notes 直接渲染到屏幕。

证据/依据：Trypke 2023 冗余效应系统综述（63 研究，两类冗余四场景）

M04

空间临近 Spatial Contiguity

cognition/multimedia-learning

相关文字与图形应相邻呈现，减少来回搜索。

✓ 正例
图 A
说明紧贴图 A 下方
图 B
说明紧贴图 B 下方
✕ 反例
图 A / 图 B
图 A 的说明、图 B 的说明、以及两图共同的注释，全部堆在右侧一栏。

导出的渲染规则：注释必须渲染在其所属图形/数据的同一容器内；禁止集中式图例注释块（图表内置图例除外）。

证据/依据：Ginns 2006 空间/时间临近元分析（摘要级登记，未推断效应量）

M05

时间临近 Temporal Contiguity

cognition/multimedia-learning

对应文字与图形应在时间上同时呈现，而非先后分置两幕。

✓ 正例
同比增量拆解
图与说明同幕同步揭示（::逐条同步::）。
✕ 反例
先播一页「图」，翻页后再播一页「说明文字」——学习者需在记忆中回取上一页。

导出的渲染规则：Renderer 把 explanations 与 visual 放在同一 Scene；不得把同一机制的图与说明拆到相邻两幕。

证据/依据：Liu / Lin / Paas 2022 中文幻灯片实验（逐条同步揭示 d=.67）

M06

分段 Segmenting

cognition/multimedia-learning

把复杂连续内容切成可自定节奏的小段。

✓ 正例
01
第一段
讲者控速
02
第二段
讲者控速
✕ 反例
六步流程一次性全部呈现，讲者无法控制节奏，听众无法分段消化。

导出的渲染规则：多步内容必须使用 data-reveal 逐步揭示，并挂到统一动效控制器（可 pause/reverse/skip）。

证据/依据：Rey 2019 分段效应元分析（Education Psychology Review 31(2)）

M07

通道 Modality

cognition/cognitive-load

图形配语音优于图形配屏读文字（避免视觉通道双载）。

✓ 正例
屏幕：图与关键词；通道：讲者口头解释。
✕ 反例
屏幕上同时出现图形 + 长段文字，且讲者逐字念出同一长段文字（视觉通道过载）。

导出的渲染规则：Stage 模式单幕屏幕文字量与图形复杂度需满足「视觉通道余量」约束：正文超过阈值时 Renderer 提示拆分。

证据/依据：Sweller 2019 CLT 修订综述（Springer OA 全文精读）

M08

预训练 Pretraining

cognition/cognitive-load

在进入复杂内容前先交代必要术语与组件。

✓ 正例
先立术语
元数据服务 / 指标服务 / 血缘 —— 三个术语各一句话。
✕ 反例
直接进入架构细节，术语首次出现即被用于论证。

导出的渲染规则：当 Scene 使用专业术语时，Renderer 在 Core Path 前部安排 Pretraining 型 Scene（或本幕内术语条）。

证据/依据：Sweller 2019；Mayer 多媒体学习原则

M09

个性化 Personalization

communication/persuasion-elm

对话式、第二人称的表达提升涉入度。

✓ 正例
「你的问题不是内容不够，而是产出不稳定。」
✕ 反例
「本方案旨在提升内容供给侧的稳定性与交付确定性。」

导出的渲染规则：对高涉入场景，标题与导语优先第二人称；Renderer 保留 authored 文案，不自动改写为公文语。

证据/依据：Petty & Cacioppo 1984 ELM（涉入度 × 论证质量 × 来源线索交互）

✕ 反例

证据/依据：Sweller 2019；项目 §23 认知负荷曲线

M12

注意线索 Attention Cueing

cognition/attention-fluency

用前注意属性（颜色、位置、大小）引导注意，而非事后加箭头。

✓ 正例
+12%
关键数字用尺寸 + 强调色
✕ 反例
在普通字号文本上叠加 5 个箭头与 3 个圈注来说明重点。

导出的渲染规则：优先用尺寸/位置/色彩编码承载层级；箭头与圈注仅在空间关系无法用布局表达时使用。

证据/依据：de Koning 2009 三功能综述（Springer OA 全文精读）

M13

断言-证据 Assertion-Evidence

presentation/assertion-evidence

标题写完整断言，正文给视觉证据。

✓ 正例

问题不在流量不够，而在::每次触达都无法沉淀::

看似的问题

真实的问题

✕ 反例

关于用户触达情况的几点说明

一段没有断言、只有话题标签的正文。

导出的渲染规则：标题必须是完整句子（断言/问题/决策），禁止话题标签式标题；话题式仅用于附录与过渡幕。

证据/依据：Garner & Alley 2013（d=0.81/0.89）；Aippersbach 2013 讲者侧 t(51)=2.62

M14

标题类型由认知任务决定

presentation/headline-system

问句/断言/主题/决策/对比/叙事六型，按 Scene 的认知任务选择。

✓ 正例

「采集用户数据，::合规吗::？」

异议应对幕 → 问句式（复述质疑）

✕ 反例

把所有标题一律改成问句（含结论幕、决策幕），导致结论被推迟到正文。

导出的渲染规则：Renderer 不做标题类型的全局变换；类型由 scene.headline.type 决定，validate_ir 要求填写 rationale。

证据/依据：Aippersbach 2013；Garner 2009 理论映射

M15

信息密度按模式决定

presentation/information-density

Stage 低密度、Reader 高密度、Print 完整 —— 同一内容模型三套密度。

✓ 正例
Stage：结论一句话
Reader：完整论述单独渲染在 wp-reader 层
✕ 反例

用同一段文字同时服务讲台与阅读，结果讲台上太密、打印稿又太简。

导出的渲染规则：Renderer 从 content.stage / content.reader 分别取值渲染到不同层；禁止共用同一字符串。

证据/依据：项目 §22/§57 信息密度策略（SUPPORTED PRINCIPLE）

M16

叙事传输 Narrative Transportation

communication/narrative

叙事通过角色-目标-冲突-转变提升情感投入，但仅适用于对应用途。

✓ 正例
冲突
账算不平
转折
换个角色
✕ 反例

在审计、合规读本、操作清单里强行插入人物故事（干扰信息检索）。

导出的渲染规则：叙事型组件（时间线/角色弧）仅用于 narrative/case/opening/summary 角色的幕；审计类不启用。

证据/依据：van Laer 2014 叙事传输元分析（76 文 / 132 效应量）

M17

说服双路径 ELM

communication/persuasion-elm

高涉入受众走中心路径（论证质量），低涉入走边缘路径（来源线索）。

✓ 正例
对决策者：给论证与数据
财务口径、敏感性、退出底线。
✕ 反例

对需要拍板的决策者只讲品牌口号与领导背书（用边缘线索替代论证）。

导出的渲染规则：Renderer 依 audience.decision_power / attitude 决定证据强度：decider 幕必须含 evidence 块。

证据/依据：Petty & Cacioppo 1984（原文扫描件逐页精读）

M18

图形选择由认知任务决定

visualization/chart-selection

先定 Comparison/Trend/Distribution/Ranking/Composition，再选图形。

✓ 正例
任务 = 排名 → 横向条形图（ranking）
✕ 反例

任务 = 准确比较量级，却用饼图/3D 饼图/双 Y 轴折线表达。

导出的渲染规则：chart.kind 由 Scene 的认知任务推导；validate_ir 校验 kind 合法性，Renderer 不得为美观更换图形。

证据/依据：Cleveland & McGill 1986（N=127 精度排序）；Heer & Bostock 2010 众包复现

M19

图表诚信 Chart Honesty

visualization/visual-perception

坐标轴、比例、口径不得误导。

✓ 正例
口径：纵轴从 0 起；样本 n=240；剔除规则见附录
✕ 反例

纵轴截断放大差异、无样本量、无口径说明、把相关性暗示为因果。

导出的渲染规则：chart 必须有 caption 交代口径与样本；Renderer 对缺失 caption 的 chart 输出 warning（validate_ir 已实现）。

证据/依据：Franconeri 2021 可视化沟通科学综述

M20

语义动效 Semantic Motion

motion/semantic-motion

动效必须承担认知任务（揭示/聚焦/连接/因果…），否则静态。

✓ 正例
连接线随流程逐步绘制（表达因果顺序）
✕ 反例

每页加一个无意义的飞入/旋转/弹跳，只为「显得高级」。

导出的渲染规则：motion_intent 必须取自 10 类语义集合；无法回答「为什么静态不够」时降级为静态或仅揭示。

证据/依据：项目 §35/§36/§37（PRACTITIONER HEURISTIC + 工程可验证）

M21

核心路径不依赖交互

interaction/interaction-patterns

不操作任何交互也能完整理解 Core Path。

✓ 正例
结论先给（无需展开）；细节放在可展开层供追问。
展开为可选
✕ 反例

关键结论只存在于 hover 提示或需点击展开的面板中——不交互就看不到结论。

导出的渲染规则：interaction 必须带 purpose；Renderer 保证主结论在静态层，交互只承载补充信息。

证据/依据：项目 §44；interaction.js 启动时扫描告警

M22

讲者-屏幕分工

presentation/information-density

屏幕承担不了的交给讲者，不要屏幕写一遍讲者再念一遍。

✓ 正例
屏幕：图
讲者：解释图背后的判断与取舍
✕ 反例

屏幕完整写出 200 字讲稿，讲者逐字念出同一段文字（双向冗余）。

导出的渲染规则：screen_role 与 speaker_role 必填；二者内容不得高度重叠（Renderer 不校验语义，由 validate_ir + 人工评审把关）。

证据/依据：项目 §58（SUPPORTED PRINCIPLE）

M23

反模式：普适规则谬误

anti_patterns/universal-rule-fallacy

把情境化启发式当成普适军规。

✓ 正例

「字少」只在 Stage 成立；Reader 必须完整。条件、机制、边界三者齐全才可入规则库。

✕ 反例

「每页最多 6 行」「标题必须是问句」「字号不得小于 24」——以无条件军规形式写入工具。

导出的渲染规则：Renderer 不得内置无条件排版军规；所有阈值为 Token 化的默认值，可被 Scene 覆盖。

证据/依据：项目 §10；knowledge/anti_patterns/universal-rule-fallacy.md

M24

反模式：技术滥用

anti_patterns/tech-abuse

能实现不等于应该实现。

✓ 正例

该内容用 2D 表更清楚 → 使用表格；3D 仅用于空间关系（本 Deck 未用）。

✕ 反例

所有数据都做 3D 柱状图、每页都加粒子背景、为显示技术能力引入 3 个库。

导出的渲染规则：render_level 逐幕选择最低充分层级并填写 rationale（L3+ 强制）；技术超出需求时降级。

证据/依据：项目 §36/§43/§47；audits/TECH_DECISIONS.md

M25

反模式：装饰优先

anti_patterns/decoration-first

先解决传播，再考虑形式。

✓ 正例

先定认知任务与信息结构 → 再选视觉表达（本画廊全部按此顺序构建）。

✕ 反例

先挑一个炫酷模板 → 再想办法把内容塞进去（内容被形式裁剪）。

导出的渲染规则：管线强制 Strategy → IR → Renderer；禁止 Input → HTML 一步生成。

证据/依据：项目 §0/§1/§55
